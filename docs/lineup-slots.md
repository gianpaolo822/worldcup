# 阵容槽位与坐标规范

本文档定义 `match-lineups.json` 的首发槽位语义、各阵型必填槽位，以及球场坐标的分层规则。

## 坐标系

| 轴 | 范围 | 含义 |
|----|------|------|
| x | 0–100 | 左 → 右（对应球员从左到右） |
| y | 0–100 | 上 → 下 |

- **客队（away）**：占据上半场（y 较小），门将靠近 y≈6，前锋靠近中线。
- **主队（home）**：占据下半场（y 较大），门将靠近 y≈94，前锋靠近中线。
- **中线留白**：约 y=43–57，避免双方前锋/后卫重叠。
- 渲染时以 `(x%, y%)` 为球员头像中心点。

## 分层（Layer）

坐标引擎按 **层** 决定 y，按 **阵型配置** 决定每层上各槽位的 x。可选 `y` 覆盖个别槽位（如 3-4-3 边锋略高于前腰）。

| 层 | 客队典型 y | 语义 |
|----|-----------|------|
| `gk` | 6 | 门将 |
| `def` | 14–16 | 后卫线（三中卫 / 四后卫 / 五后卫） |
| `dm` | 26–28 | 后腰 / 五后卫阵型的第 5 卫（见下） |
| `mid` | 24–30 | 中场 / 翼卫（三后卫阵型） |
| `am` | 33–36 | 前腰 / 攻击中场 |
| `fwd` | 41–44 | 前锋线 |

主队各层 y 在 `formationConfigs.ts` 中单独配置（非简单镜像）。

## 槽位别名

录入时推荐使用下列主槽位；别名会自动映射：

| 别名 | 映射 |
|------|------|
| `LWB` / `RWB` | `LB` / `RB` |
| `LM` / `RM` | `LW` / `RW` |
| `LCM` / `RCM` | `LDM` / `RDM` |
| `CM` | `CAM` |

## 各阵型槽位语义与必填槽位

每队首发 **11 人**，必须使用下列槽位键（`starters` 对象的 key）。

### 4-2-3-1

四后卫 + 双后腰 + 三攻击手 + 单前锋。

| 槽位 | 场上位置 |
|------|----------|
| GK | 门将 |
| LB, LCB, RCB, RB | 四后卫（左→右） |
| LDM, RDM | 双后腰 |
| LW, CAM, RW | 左前腰、中路前腰、右前腰 |
| ST | 中锋 |

### 3-4-2-1

> **三后卫必须使用 `LCB` / `CB` / `RCB` 槽位**（左→右），不要用 `LB` 表示左中卫。

| 槽位 | 场上位置 |
|------|----------|
| GK | 门将 |
| LCB, CB, RCB | 三中卫（左→右） |
| LW, LDM, RDM, RB | 四中场 / 翼卫（左→右） |
| CAM, SS | 双前腰（左、右） |
| ST | 中锋 |

**示例（韩国 3-4-2-1，m028）**

| LCB | 3 | 李期奕 |
| CB | 4 | 金玟哉 |
| RCB | 2 | 李韩汎 |
| LW | 22 | 薛英佑 |
| LDM | 6 | 黄仁范 |
| RDM | 8 | 白昇浩 |
| RB | 15 | 金纹奂 |
| CAM | 10 | 李在成 |

### 3-4-3

与 3-4-2-1 相同的后卫与中场线（**三中卫：LCB / CB / RCB**）；前场为三叉戟。

| 槽位 | 场上位置 |
|------|----------|
| GK | 门将 |
| LCB, CB, RCB | 三中卫（左→右） |
| LW, LDM, RDM, RB | 四中场 / 翼卫 |
| LW, ST, RW | 三前锋（可选 CAM 中路） |

必填：`GK, LCB, CB, RCB, LDM, RDM, RB, LW, ST, RW`（可选 `CAM`）

## 录入校验

运行 `npm run data:lineup:validate` 会检查：

1. 阵型是否在支持列表内
2. 首发是否为 11 人
3. 槽位是否与阵型必填集合一致（允许别名）
4. 坐标是否可解析（无隐藏球员）
5. 同队槽位是否过近（间距 &lt; 7）

## 迁移说明（Legacy）

**Phase 2 已完成**（2026-07）：`npm run data:lineup:migrate` 已批量迁移 30 条球队首发为标准槽位键；84 场 validate/audit 全部通过。

新录入请严格按本文档槽位填写。坐标引擎仍保留 Legacy 映射，以防外部 JSON 仍用旧键名。

**3-4-2-1 的 RW 歧义**（仅未迁移的旧 JSON）

| 情况 | RW 坐标 |
|------|---------|
| 有 RB、无 SS | RW → 右前腰位（SS 层） |
| 有 SS、无 RB | RW → 右翼卫位（RB 层） |
| 新录入 | 请用 `SS` / `RB`，勿再用 `RW` |

运行 `npm run data:lineup:validate` / `data:lineup:audit` 可检查全部 84 场阵容。
